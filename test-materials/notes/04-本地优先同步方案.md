# 本地优先同步：草案

## 目标

用户在网络不稳定时仍能编辑笔记；恢复联网后，把本地变更安全地同步到服务端。当前原型阶段先明确数据边界，不实现自动覆盖。

## 冲突场景

同一篇笔记在手机离线编辑，期间又在电脑上修改。两端恢复联网后，客户端需要比较各自基于的版本和服务端当前版本。

建议请求携带：

```json
{
  "note_id": "示例笔记标识",
  "base_version": 12,
  "local_updated_at": "2026-10-01T09:15:00+08:00"
}
```

如果服务端版本已变化，返回冲突状态和当前内容摘要，让用户选择查看差异、保留两份或手动合并。不要用设备时钟直接决定谁覆盖谁，因为设备时间可能不准确。

## 暂不纳入本轮

- 多人共同编辑同一笔记。
- 自动合并 Markdown 表格与代码块。
- 删除操作的多设备冲突恢复。

## 验收场景

1. 离线新建笔记，联网后只创建一条服务端记录。
2. 两台设备基于同一版本分别修改，第二次提交收到冲突提示。
3. 同步中途断网，重试不会重复创建笔记。
