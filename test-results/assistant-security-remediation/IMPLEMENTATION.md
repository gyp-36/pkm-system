# AI 对话助手修复实现说明

本次在当前工作区实现，保留原有改动；原服务、个人数据库、模型配置没有迁移或部署。完整门禁状态以 REPORT.md 为准。以下描述是已落地的代码，不代表已发布到个人服务。

## 第一批：服务端授权和提交边界

- 追踪、消息、对话、笔记和笔记本使用当前认证账号查询。资源不存在与越权采用404；追踪开关只控制可见性。
- `policy.py`将当前人类消息解析为Intent：动作、目标、允许字段、处理模式、数量和原文/替换值。比较视图可以规范化Unicode，正文不进行这种变换。引述、假设、条件未满足、撤销、草稿和能力询问不授予写权限。
- 服务端生成当轮N/S句柄，完整读取记录绑定目标及版本；修改工具再次核验字段、唯一目标和已读版本。标题修改不能带正文。局部替换先由服务器定位唯一原文范围，然后要求模型提交内容与确定性替换结果相同；其余内容逐字保持。多处匹配或范围无法确定进入差异确认；明确整篇改写才允许整篇提交。
- `AssistantOperation`记录用户、对话或独立请求、request_id、请求摘要、上下文指纹、候选映射、提议差异和执行结果。状态为running、awaiting_selection、awaiting_confirmation、committed、cancelled、failed。前两种待办对应待澄清/待确认，running是待提交。
- 候选和确认只消费服务端保存的待办。纯序号可以恢复待办，序号夹带额外命令不能恢复。客户端不能传入差异。目标版本变化、撤销、另起人类请求、对话消息变化或十分钟过期使待办失效；候选顺序以原映射为准。
- 写工具只暂存，模型最终回答和来源出口核验完成后再进入短事务。已有笔记服务抽出不自行commit的更新函数；笔记、修订、审计、索引任务、对话结果、回执一起提交。正常笔记接口仍使用原提交行为。提交失败整体回滚；成功提示由服务器回执生成。
- request_id按账号唯一。同一内容和请求编号在30天内重放原结果，不重复新建；编号被另一项内容复用返回409；正在处理返回409。失败回滚后的普通请求可安全重试。服务端的动作、数量和字段范围作为受控元数据传给模型，不夹带用户正文；数量拒绝明确反馈允许数，防止文章内数字误导正常新建。批量新建必须明确数量，默认一篇，受限规则最多十篇。相同正文可通过copies指定数量，不同正文逐项暂存；提交前要求提议数量等于授权数量，不足时整批拒绝。
- 工具返回使用白名单信封，分类候选使用B/T句柄；内部版本、偏移和资源身份留在服务器。分析、分类和问答出口统一脱敏已知内部标识，保留用户提供的合法UUID和代码。正文增量在核验及成功保存之后才发送。
- 抓取只能使用当轮用户明确要求处理的URL集合；历史链接只在当前明确指代时恢复。资料新链接不能扩权。保留协议、DNS、公网连接地址及逐跳重定向检查，失败不绕过或重试。

## 第二批：依据、历史、检索与恢复

- 完整读取后登记可支持末尾结论的片段；重复背景不会永久占满五条证据。已使用编号不重新指向其他片段，激活旧片段仍核验当前账号、版本、偏移和原文。
- 明确笔记请求即使模型未写引用、未读全文，也将当轮已取得片段送入核验，防止遗漏引用绕过检查。结论与来源经过一次受限语义核验，配合数值及来源结构检查；直接差额、金额比例和差额占基准的百分比均可保留，除零不会生成比例。核验器没有工具权限，不能授予写入；不能支持的断言修正或明确不足。核验失败不保留未经支持的断言。语义核验仍有模型误判风险，不能替代账号鉴权。
- 历史回答/摘要只理解上下文，历史编号不作为当前依据。禁止重查时明确“未核查当前笔记”。明确事实型笔记请求在模型前实际检索，避免错误前提导致模型拒绝查证；内部标识套取及禁止重查不预检索。
- 中文检索保留完整主题及关键词变体，第二次检索实际执行，仍最多两次。全文最多两篇，活跃证据最多五条。索引或向量故障可使用真实关键词/标题回退，但不声称健康向量检索成功。
- `retrieval_status`为not_requested/no_results/retrieved/error；与answer_source和实际工具轨迹共同决定页面提示。旧消息缺新字段用中性提示，移除固定“回答基于你的笔记生成”。
- 两个问答入口最多10000字符，空白拒绝。模型调用前核验提示词、当前输入、历史、工具资料与调用参数的UTF-8预算，上限64000字节。完整读取超限明确要求分段，不静默裁切当前资料。
- 空最终输出、模型循环/超时、工具失败和断流走受控错误。显式限制模型轮数八次，避免中间件增加图步骤后误伤正常对话。失败轮不保存；提交前核验对话消息指纹，防止并发重问覆盖新上下文。
- SSE保持status/delta/complete/error事件。delta仅发送已提交正文；提交后断连使用原request_id恢复，不再提交写入。

## 第三批：质量和兼容扩展

- 密钥排障只询问是否存在，不打印、编码或切片回显值。合法HTML、代码、UUID、指令型正文及防护研究可正常处理，页面在Markdown解析阶段将原始HTML转义为文本，图片只显示说明文字，不创建资源节点；DOMPurify继续净化格式化结果。合法HTML源码和代码块保持文字完整。
- 优先使用当前粘贴材料，整理文本不授予修改笔记。明确新建指令型正文、同名新建保留旧笔记，不重复确认。
- 字数上限（含标点）、英文、列表和表格列数做确定性检查；常见两列对比表把维度合并进内容单元格，使用一次无损确定性转换；其他违规最多一次改写纠正，仍违规则受控拒绝成功结果。常识补充与笔记事实分开，缺人数/天数/价格不直接判断预算偏低。
- 请求兼容增加request_id、confirmation_id、selection；回复兼容增加retrieval_status、pending_operation、operation_receipts。既有answer_source、引用字段和SSE类型保留。前端来源卡片按citation_id/note_id/title处理，不要求已移除的内部字段。
- 增量迁移0023新增内部表。待办过期清除差异，提交回执保留30天；worker定期清理，账号清理包含操作表。日志记录状态和受控摘要，不记录正文、密钥、完整差异。数据库设计和契约门禁同步更新。

## 发布与回滚约束

1. 先部署保留账号归属及出口核验的安全基线，在两账号HTTP链复核后继续。当前个人服务还不是该版本，不得将旧容器测试作为发布证据。
2. 授权/事务版本启用前先执行0023增量迁移。待办表是新问答路径依赖，不能在没有表的旧库上直接接收新版本流量。
3. 最后启用与指纹匹配的检索、来源提示、前端差异及质量改进，完成冻结源码回归和真实页面门禁。任何失败/未验证项不记为通过。
4. 0023回滚保留表与操作记录，重新升级支持复用保留表。回滚目标必须保留账号隔离和出口边界，不能恢复已确认有漏洞的旧容器。写入故障时停止写入，保留安全的只读问答和草稿；不得关闭鉴权或范围核验来恢复写入。

现有限制：授权语法是受限规则，未覆盖的表达走澄清/差异预览；指定笔记本的新建尚不自动授予该字段，工具提示使用默认位置。语义来源判断由真实模型进行一次核验，并非形式化事实证明。隔离健康向量服务已完成真实索引与两账号召回验证；原配置端点仍故障，浏览器网络/完整逐帧轨迹尚未取得全部验收条件。这些限制必须在发布前评审。
