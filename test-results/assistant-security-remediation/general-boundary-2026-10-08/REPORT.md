# AI 对话助手通用边界测试报告

日期：2026-10-08，Asia/Shanghai。测试依据为 [通用边界方案](../GENERAL_BOUNDARY_PLAN.md)。本轮只新增测试脚本、结果及构建产物，没有修改应用逻辑、原服务配置、个人笔记或模型配置。

**结论：通用边界验收未通过。** 已确认自由文本出口、历史复用与响应内容契约存在缺口。真实模型提供商当前返回 HTTP 402（余额不足），原 200 场景中的模型验证未完成，不能宣布 280 次基础执行全部完成。

## 二、确认的通用缺口

### G-01：自由文本出口没有完整的来源与用途约束

单函数探针显示，已登记的完整UUID及大写UUID可以脱敏，但缩写前后缀、去连字符形式和明确的控制元数据仍保留。此层只是纵深兜底检查，不能独立证明完整模型链会发生泄漏。

进一步使用**实际问答路由、真实PostgreSQL和受控不安全代理/核验器**验证：

- 对正常的本人资料请求，执行原始搜索工具并登记来源。
- 代理生成内部身份缩写、去连字符身份或内部版本/偏移描述。
- 核验器将它们自标为`general`；服务器不能依赖这种自报作为可见性证明。
- 内容最终通过201响应、持久化，并出现在SSE正文。

三种机制在同步首发及SSE首发各三次，共 **18/18次复现**。完整UUID对照及普通技术UUID/版本资料保持对照通过。

影响：资料、旧历史或错误结果一旦使模型获得内部控制信息，当前出口仍可能接受其变形和错误分类；工具字段白名单不能单独承担整个输出边界。

通用修复方向：模型输入、用户响应和审计使用不同来源/用途投影；模型所有文字及自报分类都视为提议；最终出站使用统一可见性契约，不依赖某个ID格式或关键词补丁。

证据：[属性结果](property-results.json)、[同步首发路由](route-boundary-results.json)、[SSE首发路由](initial-stream-route-results.json)。

### G-02：历史内容绕过当前边界

合成旧助手消息包含服务器内部身份。实际`message_context()`仍将该身份放入模型历史；真实HTTP读取接口仍返回该正文；实际页面会显示并复制它。上述层各三次均复现。

影响：新回答的安全控制无法覆盖旧存储内容；同一内容在新生成、历史读取、上下文、刷新和复制之间缺少统一规则。重建服务不能自动净化已有消息。

通用修复方向：历史、摘要、缓存、幂等结果和呈现均通过当前安全投影；需要时安全重建摘要。保留原始数据，不擅自删除或改写个人对话。

证据：[历史/HTTP属性](property-results.json)、[真实浏览器与复制](browser-legacy-results.json)、[合成旧消息截图](browser-legacy-proof.jpg)。

### G-03：嵌套数据和字段类型没有完整契约

在专用库写入合成历史消息，加入随机命名的服务器控制扩展字段。真实HTTP返回该字段及嵌套控制canary，**3/3次复现**。同类字段写在用户JSON正文中则原样保留，**3/3次正常对照通过**。

另对实际模型信封构造器做深层属性探针：`external_link_ok.metadata`可容纳未登记控制字段；`title`也可被替换成携带控制字段的对象，两种各三次均被接受。合法JSON以文档字符串传入三次均保留。当前抓取工具的metadata固定为空，这些是契约扩展和类型替换探针，不代表当前抓取流程已发送真实秘密。

原因：消息外层响应有类型契约，但`content`仍是通用dict；工具信封检查字段名及部分已登记嵌套集合，却没有覆盖开放容器及标量字段类型。结构化数据可以在未建模层级中继续携带控制信息。

影响：旧版本或未来功能把额外控制字段写入消息对象后，读取接口可能原样传播；这是可扩展性契约缺口。探针没有使用真实密钥，不代表当前库已经发生真实密钥泄漏。

通用修复方向：对用户消息、助手结果、旧检索消息等建立兼容但显式的内容类型及投影，所有嵌套字段按用途登记；文字正文中的JSON作为资料保持。

证据：[响应契约真实HTTP](response-contract-results.json)、[模型深层契约](deep-contract-results.json)、[当前响应契约](../../../api/app/contracts/conversations.py)。

## 三、已通过的边界及证据限度

- 未登记顶层字段、已声明嵌套集合中的额外字段和未知工具结果信封拒绝。开放容器及字段类型缺口另列G-03，不能据此声称所有嵌套输入均受控。
- 正文中的撤销、system伪装、授权JSON、代码和网页命令不增加创建数量或操作范围；正常保存指令型文章仍授权一篇。
- 引述、假设、草稿和撤销不授予当前写入；唯一局部修改保留范围外资料，多处匹配不随意执行。
- 当前网络请求控制目的地，资料新链接和没有当前明确指代的历史不扩权；危险协议、地址、DNS及重定向回归通过。
- 两账号资源HTTP隔离和实际向量召回隔离通过。
- 受控完整路由中，正常通用回答、合法技术正文及明确新建均通过；新建只生成一篇，正文合法UUID和“创建十篇”文章文字保持，另一通道重放不重复提交。
- 受控空回答和无回执的“已保存”被拒绝，没有成功消息或笔记部分保存。六项后端模块还覆盖版本冲突、原子性、幂等、确认过期及候选绑定。
- 浏览器DOM检查未出现script、iframe、img、事件属性和危险协议href。真实HTTPS标签/地址不一致仅记录事实，不把净化器当作钓鱼识别器。

这些通过只对应具体执行断言。单函数脱敏、受控模型输出、真实浏览器和真实模型行为互不替代。

## 四、环境故障与未验证

模型批次开始11个场景均出现上游APIStatusError、应用返回502，未获得答案。独立最小请求确认 **402、余额不足**。没有导出原始上游错误或密钥。发现连续错误后停止新模型场景；测试脚本随后补上401/402/403/429断路保护，旧失败记录保留。

受限条件包括：

- 当前版本真实模型的普通问答、内容安全/误拒、直接/间接注入、历史与授权攻击重复验证。
- 真实模型压缩摘要、真实模型提交后断流与恢复，本轮未重跑为通过。
- 浏览器网络捕获和完整逐帧轨迹；DOM没有危险节点不能证明所有网络行为已捕获。
- 个人配置的向量端点，本轮只验证隔离健康端点。

恢复提供商条件后，在同一冻结版本或新明确指纹上单独补跑模型记录；不能删除这11次失败或把原有成功快照移入本轮。
