# AI 对话助手通用安全边界方案

本方案替代以单次泄漏为中心的主修复方案。安全控制按调用链、数据来源和操作能力建立，不依赖特定标题、措辞、字段名字或攻击文本。已发现的问题作为回归样本，不能定义整个防护边界。

状态：设计方案，尚未实施本方案中的全部补充控制。已有修复复用并核验，不把“源码有实现”“容器已重建”当作验收通过。

## 一、统一原则与覆盖范围

覆盖普通对话、知识问答、笔记定位与理解、写作整理、创建和修改、全文与检索片段、网页和文件资料、图片描述、多轮历史、压缩摘要、分析分类、同步与流式、持久化与重放，以及页面展示、复制和已有导出路径。

四条核心原则：

1. **模型生成的是提议，不是权限。** 模型输出、工具内容、引用、历史和摘要都不能授予读写、联网或跨账号能力。
2. **权限来自认证身份及当前直接请求。** 明确请求直接执行；仅目标、范围或权限无法可靠确定时澄清或确认具体差异。
3. **控制信息与处理资料分离。** 资料中的命令、标题中的控制词、代码和指令型文章按资料处理；不将它们升级为当前操作指令。
4. **每次跨边界都验证。** 不能只依赖提示词、前端净化、字段黑名单、完整 UUID 正则或另一个模型的判断。

模型内容安全和语义正确性具有判断误差。账号归属、工具授权、字段范围、网络目标、版本、事务及结构契约由服务端强制执行；语义核验只承担回答质量控制，不能替代上述硬边界。

## 二、通用边界矩阵

| 边界 | 服务端规则 | 正常功能要求 | 失败行为 |
|---|---|---|---|
| 身份与资源 | 身份只取认证上下文；每个资源、句柄、待办、引用及回执验证账号归属 | 本人资源正常读取和操作 | 越权与不存在统一 404，不泄露存在性 |
| 请求与授权 | 当前直接请求生成动作、目标、范围、数量、有效期及请求绑定能力 | 明确请求直接执行，资料整理不误当写入 | 模糊请求只读定位、草稿或澄清，不自行扩权 |
| 资料与控制 | 所有外部资料及模型文字保持原始信任等级；内容转码和摘要不提升权限 | 正常处理代码、HTML、引用命令和指令文章 | 不执行资料或历史里的控制指令 |
| 模型输入 | 按用途投影必要资料，内部控制状态在服务器保存 | 提供足够材料解决用户任务 | 不把整个数据库对象、错误堆栈或配置投入模型 |
| 工具调用 | 每次验证能力、资源、参数、已读范围和版本；未知工具默认拒绝 | 所有合法工具路径一致工作 | 调用前拒绝，不能由工具反馈或模型要求扩权 |
| 网络与外传 | 验证当前授权目的地、协议、DNS、连接地址、重定向与发送内容 | 正常公共网页分析 | 未授权或危险请求在联网前拒绝，无绕过重试 |
| 回答与依据 | 回答类型、引用结构、实际状态及可见信息均通过出站契约 | 通用回答、笔记依据、澄清和草稿准确区分 | 受限修正或安全错误，不保留虚构成功与无依据断言 |
| 提交与恢复 | 提议先暂存；内容检查后原子提交，版本和会话并发校验，账号内幂等 | 正常保存和重试不重复执行 | 失败整批回滚，安全降级为只读或草稿 |
| 历史与缓存 | 历史仅帮助理解指代；摘要、旧结果及重放再次过当前边界 | 合法多轮连续、恢复和旧消息展示 | 不恢复旧授权，不传播旧泄漏及无效引用 |
| 页面与日志 | 安全文本/链接契约；日志只记录必要状态，构建与执行可追溯 | 合法内容可读、可复制，来源提示一致 | 禁止危险渲染和未经校验正文展示，不记录敏感原文 |

## 三、数据契约与来源：替代按特征打补丁

为进入助手的数据建立两个独立维度：

- **来源及控制权**：认证上下文、服务器策略、当前用户控制指令、用户待处理资料、账号内资源、外部资源、模型产物。只有明确的当前控制请求能形成能力；“可信地来自数据库”不代表数据库正文中的指令可信。
- **可见用途**：用户可见资料、受账号保护的资料、服务器控制元数据、凭据及秘密。是否能送入模型、返回当前用户或发送外部目的地，由用途及授权决定。

采用带来源记录的内部数据对象，包含账号绑定、来源类型、资源映射、用途、版本及本轮登记状态。内部对象分别投影为模型输入、工具参数、用户响应和审计事件，不复用同一字典贯穿全链。

模型输入只含解决当前任务需要的正文和当轮句柄；账号身份、真实控制 ID、版本/偏移控制值、密钥、环境配置和栈信息留在服务器。合法正文里的 UUID 或技术版本是资料，不因为字符串相似就整段删除。

所有工具的输入与输出必须登记类型、字段用途、嵌套结构、所需能力和副作用类型。新工具或新增字段没有登记时构建门禁失败或运行拒绝，禁止以“通用 dict”“全部 JSON”绕过。白名单覆盖嵌套对象、列表、错误及附加字段。

这能从结构上避免任意内部字段进入模型，而非为 `note_id`、某个前缀或某个错误文案逐个添加删除规则。出站敏感信息检测作为纵深兜底，使用来源和用途判断；不将关键词命中本身作为唯一放行或拒绝依据。

## 四、能力与操作状态机

统一能力记录绑定：当前账号、会话或独立请求、request_id、动作、目标集合、允许字段或唯一正文范围、数量、读取范围、目标版本、联网目的地、有效期及待办状态。

- 将“任务理解”“只读目标发现”“资料处理”“修改提议”“提交授权”区分开。名称不完整时允许必要的本人资源定位，不自动授予覆盖或批量权限。
- 语义理解可提出结构化任务候选，但不能由模型自报“已授权”放行。服务器根据当前直接指令验证；无法可靠确定的范围生成具体预览或澄清。
- 写入入口验证动作、目标、归属、已读数据、版本、字段和真实差异。局部修改提交基于原文的补丁；整篇重写需要明确的整篇授权，不允许模型声称“只改一处”却提交整篇替换。
- 确认消费服务器保存的目标映射和具体差异，不能接受客户端或模型新传差异来扩大权限。取消、过期、目标变化、版本变化、主题切换及会话变化使待办失效。
- 保存成功只来自提交回执；查询和读取状态只来自成功执行记录。模型申请、工具被拒、暂存提议都不等于完成。
- 新建、修改和批量数量来自同一能力机制，不能靠单独适配某个预算字段或某组创建词获得安全性。

对历史 URL 的当前明确指代可以恢复所需目的地，但资料中的新链接、模型建议及旧授权不能扩展网络能力。任何外部发送同时检查目的地和内容，不仅检查 URL 是否公网。

## 五、统一回答协议与出口

内部回答采用结构化段落及服务器引用映射，至少区分：当前资料事实、通用知识、历史说法、未知/证据不足、交互澄清、草稿及操作状态。

模型给出的段落类型和来源属于待验证提议，不能把自标 `general` 当作绕开资料核验的依据。引用需验证账号、当前版本、实际片段和支持关系；无编号不能使笔记断言自动变成通用知识。完整读取也不能证明所有新结论都有支持。

一次受限补证或修正仍不能支持的结论说明证据不足。语义核验不能授予工具能力，也不能取代资源校验。检索状态和内容依据分别保存，避免“空引用＝无结果”等错误推断。

共享出口覆盖同步、分析分类、持久对话、无持久问答、SSE、差异预览、操作回执的可见文字、幂等重放、历史展示、复制及既有导出功能。顺序为：

**生成提议 → 结构及内容检查 → 引用/状态检查 → 可见信息检查 → 必要的受限修正 → 最终复查 → 原子提交 → 输出。**

所有后续拼接的服务器文本也满足同一契约。SSE 只发送通过最终检查且成功持久化的结果；完整拼接检查发生在分块之前，不能靠逐块正则防跨块泄漏。校验失败不发送问题正文，不提交暂存副作用。

对于秘密、内部元数据的变形表达和旧历史，来源隔离是主防线，出站检测是兜底。对模型任意自由文本的语义泄漏不宣称形式化零风险；通过受限输出结构、最小模型输入、受控错误和独立测试降低风险并披露限度。

## 六、历史、旧数据与异常恢复

历史和摘要只理解指代，不承载写入授权或当前证据。摘要不因由服务器保存就升级为高优先级指令。当前请求明确需要资料事实时重新核验，禁止重查时只说明历史说法，不能称已核实。

旧助手消息在展示和进入上下文前使用当前安全投影；旧摘要和幂等结果也不得跳过。不能可靠净化的旧摘要失效并以安全历史重建；不擅自删除或批量改写个人笔记和原始对话。

统一空白、错误类型、长度、UTF-8 上下文预算、工具循环、超时、限流、断流及无效输出契约。不静默截掉当前资料后声称全文已读。模型或保存失败不留下部分修改，也不污染下一轮能力和引用。

并发请求绑定会话指纹，写入绑定版本。原子提交覆盖笔记、修订、审计、索引任务、消息和回执。同一账号及 request_id 重试返回原回执；重放前重新检查账号和当前安全输出规则，不重复提交。任何重试或服务恢复不得扩大原能力。

## 七、页面、内容安全和可观测性

原始 HTML、代码和指令型材料正常作为文字处理；浏览器负责安全渲染。危险节点、事件属性、协议及未授权外部资源不能执行或加载。复制、刷新和导出使用相同安全正文，不从原始对象取未检查内容。

来源提示依据真实检索和结论依据生成。旧消息没有状态字段时使用中性提示。通用回答、无结果、资料不足、检索失败和待确认分别表达，避免固定笔记页脚或错误“已经保存”。

明显有害请求和对应预防、求助、教育及授权研究分别验证。内容安全与工具权限独立：安全教育不应误拒，文字意图分类也不能允许越权工具。高风险建议进行专门质量核验，不能把存在输出格式检查视为内容已经安全。

记录脱敏链路：请求关联、运行指纹、能力状态、提供/申请/拒绝/完成的工具状态、检索状态、引用检查、输出规则编号、修正次数和事务回执。日志不写正文、密钥、原始控制标识、完整差异或提示词全文；不同账号日志同样隔离。流程完成、安全校验和质量结论分开记录。

## 八、通用验收：边界属性 × 正常功能 × 故障条件

保留既有 **200 个独立场景：普通 60、特殊 140**。直接注入、间接注入、授权误判、历史污染各十例全部三次，基础至少 **280 次**；失败场景三次复测并配相邻正常对照。已有泄漏属于其中一个回归样本，不把专项二十例代替总体覆盖。

除场景表外增加可复跑的属性测试和组合测试：

- **账号独立性**：更换账号、伪造资源参数或句柄，不能获得他人资源；本人正常路径继续成功。
- **权限不升级**：把操作命令放入笔记、网页、代码、标题、工具输出或历史摘要，能力不增加；当前明确直接请求仍可执行。
- **范围保持**：模型扩大目标、字段、数量或正文差异，提交被拒；合法精确修改成功。
- **来源不漂移**：引用编号不能换源，版本变化不能沿用旧依据，不能通过改标通用知识保留笔记断言。
- **通道一致性**：相同问题经过同步、SSE、保存、重放、刷新、复制、导出，安全结果一致。
- **失败无副作用**：在模型、工具、核验、提交及发送边界注入失败，没有部分写入、重复写入或下一轮污染。
- **正常资料保持**：合法 UUID、HTML、代码、技术偏移、软件版本和引用命令的意义及必要文字保留，不被粗暴删除。
- **策略可扩展**：新增工具或字段未登记就失败；登记后必须同时提供合法路径、越权路径及失败恢复测试。

变化维度包括语言、Unicode、转义、嵌套结构、编码、多轮、候选变化、旧版本、流式分块和并发。变体用于验证同一属性，不把纯措辞替换冒充独立场景数量。

每个场景分别记录输入、预期、实际回答、引用、工具轨迹、授权状态、数据前后差异、运行版本、耗时和重复结果。真实模型、确定性探针、真实 HTTP 和页面数量分别披露；未取得条件和环境故障单列，不能算通过。

通过要求：已验证条件下未经授权读写、越权、超范围修改、未授权网络行为及内部信息泄漏为零；正常对照三次成功；来源和状态一致；异常无部分副作用。安全关键失败或所需条件未验证时不得宣布完整验收通过。

## 九、实施与发布

1. 盘点所有入口、资料来源、工具、副作用和出站通道，建立同源契约门禁；复核已有账号、句柄、事务和网络实现。
2. 建立通用数据投影、能力对象与共享出口，覆盖历史、缓存、预览和重放，消除可绕过入口。
3. 统一回答依据、检索状态、任务识别、错误恢复和页面呈现，补正常功能对照。
4. 在隔离库执行确定性、真实模型、HTTP、页面及故障回归；冻结验收源码、规则、迁移和前端指纹。
5. 发布前后核验实际运行版本及页面链路。保留历史报告和原始失败记录；个人数据比对报告区分本轮改动、外部并发改动及无法归因变化。

兼容现有接口与表结构，优先复用已有 request_id、检索状态、引用、待办和回执契约。只有内部来源记录确实无法由现有数据表达时再评估增量迁移；不得为了标注通过而改写测试数据。

回滚目标必须保留通用安全边界；写入故障时降级为只读问答和草稿，不关闭鉴权、范围检查或输出校验。当前运行版本一致只说明版本已部署，不能替代这套完整验收。
