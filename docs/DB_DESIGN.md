## 设计约束

`0019_note_digests_reminders` 新增三张账号归属表：`pkm_digest_settings` 保存日报、周报开关、北京时间计划与下次运行点；`pkm_digest_runs` 保存周期、状态、来源版本和生成的 `note_id`，以 `(user_id, kind, slot_key)` 唯一约束防重复；`pkm_note_reminders` 保存一次性提醒。报告正文仍是普通 `pkm_notes`，通过任务关联保留报告身份，人工编辑后也不再作为后续报告证据。

`0021_optional_reminder_note` 将 `pkm_note_reminders.note_id` 改为可空。空值代表独立提醒；关联提醒仍须校验同账号活跃笔记，删除来源笔记后隐藏。独立提醒照常出现在日程、待办和工作台，但不进入笔记日报/周报证据。

`0022_audit_observability` 建立两层日志结构。`pkm_audit_events` 是业务语义层，追加 `request_id`、`actor_id`、`outcome`、`before`、`after`（全部可空，旧数据语义不变）；`pkm_access_logs` 是请求层，记录方法、路径、状态码、耗时、IP 与 UA。分层的理由是写入者不同：业务审计与业务共用一个事务，业务回滚时一并撤销；访问日志由请求中间件用**独立会话**写入，因此越权、冲突、校验失败等未成功的请求也能留痕。两层之间按 `request_id` 关联。

- 所有应用表使用 `pkm_` 前缀；当前迁移包含 26 张业务表（其中 4 张为扩展功能表：笔记模板、Markdown 图片引用、日报/周报设置与任务、日程提醒），Alembic 元数据表 `pkm_alembic_version` 单独计数。
- 数据库没有外键。服务从登录态取得 `user_id`，在事务中核对关联对象的归属及 `deleted_at IS NULL`。笔记与标签、笔记本的关系仍用 UUID 记录。跨账号或不存在的资源返回 404；直接 SQL 可绕过服务校验，因此需要巡检。
- 有限取值列存 `smallint`，代码的 `IntEnum` 固定编号；API 仍返回语义字符串。开放文本仍用 `varchar`、`text`，审计受控详情使用 `jsonb`。
- `created_at` 由数据库 `now()` 生成。账号、会话、笔记本和标签的 `updated_at` 由触发器维护；笔记及索引任务由业务代码维护。`deleted_at` 用于账号、笔记本、标签、笔记的逻辑删除。修订和审计是追加记录，不设置 `updated_at`。
- `pkm_user_sessions` 只在登录时插入、退出时撤销；普通请求只读取，不刷新活跃时间。Token 仅以 SHA-256 摘要保存。
- AI 对话按账号持久化；每次成功提问在同一事务中保存用户问题、Agent 回答和已核验引用，历史消息按时间排序读取。超过 16 条消息后，较早历史可压缩为会话级 PostgreSQL 摘要检查点；完整消息保留为事实来源，摘要不作为笔记证据。业务服务验证会话归属，不依赖外键；现有 JSONB 可兼容旧版检索快照消息。
- 文件版本二进制保存在 API 专用的持久卷；`pkm_note_file_versions` 记录账号、笔记、原名、格式、大小、哈希和存储键。提取内容保留在笔记的检索正文与 `pkm_note_text_blocks` 位置表，`pkm_note_chunks.location` 随索引片段保存定位信息。
- 网页抓取结果进入 `pkm_link_drafts`，该表不参加正式笔记搜索或导出。用户确认发布后，创建一条 Markdown 笔记并将来源 URL 写入 `pkm_notes.source_url`。
- 用户导入的 Markdown 模板保存在 `pkm_note_templates`，按账号隔离；模板包含名称、创建笔记时使用的标题和 Markdown 正文，不参与笔记搜索、索引和导出。系统内置模板由前端提供，无需写入数据库。

## 事务和生命周期

- 创建或编辑笔记时，当前笔记、标签关联、版本快照、索引任务与审计事件在一个事务中提交。编辑需匹配 `version`，成功后版本递增；只有标题或正文实际变化才递增 `content_version` 并排队索引。每篇笔记最多一个活跃索引任务，新编辑将任务合并到最新内容并延迟 8 秒执行。
- 删除笔记时写 `deleted_at`，保留正文和修订；列表、读取、检索和 worker 均跳过已删除笔记。已删除笔记进入回收站，保留 30 天后由 `ingest-worker` 每日维护窗口到期自动永久清除，期间可由用户恢复或主动彻底删除（见[完整字段字典](DATABASE_DICTIONARY.md) 与 `app/knowledge/archive.py`）。
- 删除笔记本时将活跃笔记转为未分类；删除标签时解除当前关联。受影响笔记生成新版本和修订快照，但不重新计算内容向量；已删除分类名可复用。
- 物理清理按消息、对话、片段、当前标签关联、任务、修订、审计、访问日志、登录会话、笔记、标签、笔记本、账号的顺序显式执行。访问日志含 IP 与 User-Agent，属个人数据，随账号删除一并清除。当前不提供账号或对话的永久清除 API。
- 访问日志与业务审计不参与任何业务读取路径，仅供安全追溯与排障。中间件跳过 `/health/*`、`/docs`、`/openapi.json` 与静态资源，避免心跳淹没日志表；写入失败只记 warning，绝不影响主流程。
- 两层日志的保留策略不同。`pkm_access_logs` 是取证素材，按 `ACCESS_LOG_RETENTION_DAYS`（默认 90 天）分批清理，随 `ingest-worker` 每日维护窗口执行；`pkm_audit_events` 是变更账本，不设自动过期。永久清除笔记时不再删除该笔记的审计行——审计必须比笔记活得久，`entity_id` 指向已不存在的实体是预期行为；只有账号注销才清除其审计。清理逻辑见 `app/ops/maintenance`，排障查询入口为 `scripts.query_audit`（枚举还原、敏感键脱敏，不面向终端用户）。
- 后台任务没有 HTTP 请求，但同样写入审计。worker 用被处理单元自身的 ID（`IndexJob` / `FileIngestJob` / `DigestRun` / `LinkDraft`）作为 `request_id` 绑定上下文，使 worker 日志行与它产生的审计行共用同一个可检索标识；字段名不新造，以便两层日志共用同一查询入口。
- 上述两层结构的完整改造过程——改造前的覆盖率盘点（写接口 18/54）、三阶段实施与三处与原设计的偏差说明——归档于 [操作日志能力评估与改造方案](archive/AUDIT_LOG_REDESIGN.md)，本文只保留结论。

参考 Obsidian 的版本历史与 Notion 的分类、历史产品能力，但不推断其内部表结构。M1 使用 Markdown 笔记；M3 增加文件版本、提取文本位置和网页草稿结构，不保存文件内容在数据库中。具体字段见[完整字段字典](DATABASE_DICTIONARY.md)。


## AI 对话操作记录（0023）

`pkm_assistant_operations` 是服务端授权和幂等账本，不进入模型资料或普通笔记检索。按登录账号核验，不信任客户端提供的用户或目标参数。

| 字段 | 用途 |
|---|---|
| id / user_id / conversation_id | 操作句柄、账号和可选对话归属 |
| request_id / request_hash | 同账号请求唯一；相同请求返回原结果，内容不同返回409 |
| context_fingerprint | 消息集合指纹；并发增加消息或重问使旧待办失效 |
| status | running、awaiting_selection、awaiting_confirmation、committed、cancelled、failed |
| intent | 受限规则解析的动作、字段、范围、数量；不从资料或模型回答授予权限 |
| proposal | 候选与版本映射、原文及具体差异；仅待办阶段保存 |
| receipt | 已保存回答或待办回执，用于同请求重试 |
| created_at / expires_at | 待办显示后10分钟失效；完成回执保留30天 |

唯一约束为 `(user_id, request_id)`；索引覆盖账号/对话和过期时间。不新增外键，延续当前服务端归属检查策略。定时清理过期待办的正文与差异，失败/取消记录30天后清除，账号永久清理同时清除此表。日志仅记录动作、字段名、状态和受控错误类别。

代理工具只暂存提议。短事务重新核验目标归属、读版本和未授权区域，随后一次提交当前笔记、修订、审计、索引任务、对话消息和操作回执。任一阶段失败均回滚；同步与SSE正文均在提交后发送。现有普通笔记PATCH复用不自行提交的服务，并保持原接口提交行为。对话行和目标笔记行在提交时加锁；模型调用期间不持有这些锁。

迁移是增量兼容的。`0023` 的降级函数保留操作表，避免回滚应用丢失幂等证据；回滚应用不得关闭安全检查。遇到写入异常应保留只读问答/草稿能力，停止新写入，不能绕过账本直接调用旧写工具。

### 对话正文的来源证明与当前投影（2026-10-08）

本轮不新增表或迁移。`pkm_assistant_messages.content` 可保存服务器构造的 `_literal_sources`：来源笔记、版本、字段、原文范围及摘要。它是内部来源证明，不作为模型输入或 API 字段。历史读取使用当前账号重新核验归属、版本、范围和摘要，过期或无法验证的证明不授予文字资料豁免。合法用户文本保持，未登记的服务器扩展字段仅留存原始记录，不进入公开投影。幂等回执重放同样经过当前响应投影。原始消息和笔记不会被读取时的投影修改。
